# Seeds

| File | Written by | Role |
|---|---|---|
| `regulatory_actions.csv` | `scripts/_build_regulatory_actions_seed.py` (hand-transcribed rows) | sourced record |
| `rule_segments.csv`, `rule_code_resolution.csv`, `rule_hts_lists.csv`, `list_versions.csv`, `duty_families.csv`, `evidence_catalog.csv`, `action_evidence.csv` | `scripts/_build_rule_seeds.py` | machine-readable restatement |
| `boundary_fixtures.csv`, `family_fixtures.csv` | **by hand, static** | expected results |

The two fixture files are written by a person from the sourced record, not generated by code, and must not be
generated from the models they test (that would be self-verification). Change them only when the sourced record
changes, and record why in the commit message.

- `expected_applies`: rules that apply at `at` (`;`-separated, sorted).
- `expected_uncertain`: rules whose applicability cannot be decided at `at` from the sources: a boundary known only
  by its day (the whole day is uncertain), or an exception list known only from a later revision.
- `expected_auto`: applying rules whose resolution status (code-level if given, else the segment's) is `resolved`.
- `family_fixtures.csv`: per duty family, `applies` / `uncertain` / `none` / `not_modelled` (MFN is not modelled).
